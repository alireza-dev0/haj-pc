# Haj PC Admin Dashboard — Design System

> این فایل مرجع طراحی پروژه است. هر کامپوننت یا صفحه‌ای که ساخته می‌شود باید دقیقاً از این قوانین پیروی کند. اگر جایی این سند با حس‌وحال کلی (premium / calm / minimal) در تضاد بود، اولویت با همین سند است.

---

## 0. Context

- محصول: پنل ادمین فروشگاه قطعات کامپیوتر «Haj PC»
- زبان: فارسی، **RTL** (بدون نسخه انگلیسی در این فاز)
- استک: Next.js (frontend) + NestJS (backend) + Tailwind (theme tokens در `globals.css`)
- نوع UI: فقط پنل مدیریتی (بدون storefront، بدون سبد خرید)
- Mood: Premium, Technical, Professional, Minimal, Calm — **نه** گیمینگ، **نه** نئون، **نه** شلوغ

منبع رنگ‌ها و توکن‌ها: `globals.css` (بلاک `@theme inline`). هیچ‌وقت hex مستقیم توی کامپوننت‌ها ننویس — همیشه از این متغیرها استفاده کن.

---

## 1. RTL & Persian Rules (مهم‌ترین بخش — قبل از هر چیز بخون)

این پروژه صرفاً یک دشبورد انگلیسی نیست که rtl شده باشه؛ باید از پایه RTL-native طراحی بشه.

### 1.1 جهت کلی صفحه

- `<html dir="rtl" lang="fa">` روی کل اپ.
- **سایدبار سمت راست** قرار می‌گیرد (سمت "start" در RTL). هدر بالا، محتوا سمت چپ سایدبار.
- هیچ‌وقت از `left-*`, `right-*`, `pl-*`, `pr-*`, `ml-*`, `mr-*` مستقیم استفاده نکن. به‌جاش از کلاس‌های **logical** تیلویند استفاده کن که خودشون با dir سازگار می‌شن:
    - `ps-*` / `pe-*` به‌جای `pl-*` / `pr-*`
    - `ms-*` / `me-*` به‌جای `ml-*` / `mr-*`
    - `start-*` / `end-*` به‌جای `left-*` / `right-*`
    - `text-start` / `text-end` به‌جای `text-left` / `text-right`

    دلیل: اگه یه روز نسخه انگلیسی هم اضافه شد، هیچ کلاسی دستی برعکس نمی‌شه.

### 1.2 آیکون‌ها

- آیکون‌های **جهت‌دار** (chevron برای back/next، arrow برای "برو به"، آیکون undo/redo) باید در RTL آینه (mirror) بشن.Metadata
- آیکون‌هایی که **نباید** آینه بشن: لوگو، آیکون‌های وضعیت (چک‌مارک، ضربدر، هشدار)، آیکون چارت/گراف، آیکون‌های media (پلی، پاز)، آیکون‌های اشیاء واقعی (سبد خرید، پرینتر، ...).
- کتابخانه پیشنهادی: `lucide-react` — stroke width ثابت (۱.۵–۲px)، سایز استاندارد در نویگیشن: ۱۸–۲۰px، مونوکروم (رنگی نه، مگه برای وضعیت).

### 1.3 اعداد

- **همه‌ی اعداد دیتا (قیمت، موجودی، شماره تلفن، شناسه سفارش، درصدها) با ارقام لاتین `0-9` نمایش داده می‌شن**، نه ۰۱۲۳ فارسی. فقط برچسب‌ها و متن فارسی هستن.
- چون این اعداد داخل یک context راست‌به‌چپ قرار می‌گیرن، باید داخل یک عنصر با `dir="ltr"` و کلاس `tabular-nums` بسته بشن تا:
    1. ترتیب رقم‌ها برعکس نشه (مخصوصاً اعداد چند رقمی، تاریخ، شماره تلفن، مبلغ با اعشار)
    2. عرض ارقام یکسان باشه (برای ستون‌های عددی توی جدول)

    ```tsx
    <span dir="ltr" className="tabular-nums">۱۲۵,۰۰۰,۰۰۰</span> ❌
    <span dir="ltr" className="tabular-nums">125,000,000</span> ✅
    ```

- فرمت پول: عدد لاتین + واحد فارسی جدا، مثلاً: `<span dir="ltr">۲,۵۰۰,۰۰۰</span> تومان` → در عمل: `2,500,000 تومان`.

### 1.4 تاریخ

- تاریخ نمایشی به کاربر همیشه **شمسی (جلالی)** است، حتی اگه در دیتابیس/API به‌صورت ISO (میلادی) ذخیره و رد و بدل بشه.
- تبدیل فقط در لایه UI انجام بشه (نه در دیتابیس). از یک کتابخونه سبک مثل `jalaali-js` یا `date-fns-jalali` استفاده کن.
- فرمت پیشنهادی نمایش: `۱۴۰۳/۰۵/۲۹` (ارقام طبق قانون ۱.۳ لاتین‌اند، پس در عمل `1403/05/29`).
- برای فیلترهای تاریخی (مثلاً چارت فروش) از تقویم شمسی در date-picker استفاده کن.

### 1.5 چارت‌ها

- کتابخونه‌های چارت (recharts و مشابه) به‌صورت پیش‌فرض LTR ساخته شدن و اگه مستقیم توی یه container با `dir="rtl"` بذاریشون، محور X و ترتیب داده‌ها معکوس/بهم‌ریخته می‌شه.
- **راه‌حل:** کانتینر چارت رو مستقل با `dir="ltr"` بپیچون، ولی عنوان چارت و لیبل‌های اطرافش (که فارسی‌اند) بیرون از این کانتینر و RTL بمونن.
- محور زمان (تاریخ) در چارت «فروش در طول زمان» باید از چپ به راست بره (قدیم → جدید)، یعنی جهت طبیعی چارت حفظ می‌شه، فقط جعبه دورش RTL نیست.

### 1.6 جدول‌ها

- هدر و متن ستون‌های متنی (نام مشتری، نام محصول): راست‌چین (`text-end` چون در RTL یعنی راست).
- ستون‌های عددی (قیمت، تعداد، مجموع): هم راست‌چین می‌مونن (چون خود جدول RTL است) ولی خود عدد داخلش با قانون ۱.۳ (`dir="ltr" tabular-nums`) رندر می‌شه تا رقم‌ها بهم نریزن.
- اکشن‌ها (ویرایش/حذف) همیشه در ستون سمت **شروع جدول (راست)** یا آخرین ستون سمت چپ — یکی رو انتخاب کن و در کل پروژه ثابت نگه دار (پیشنهاد: آخرین ستون، سمت چپ‌ترین، چون چشم معمولاً اونجا دنبالش می‌گرده).

### 1.7 فرم‌ها

- Label بالای input، راست‌چین.
- Placeholder و متن‌های راهنما فارسی، ولی اگه فیلد عددی/تلفنه (مثل قیمت محصول)، input خودش `dir="ltr"` و `text-left`... در عمل چون Tailwind logical داریم: `dir="ltr"` صریح روی خود input بذار (این یکی استثناست، چون کاربر داره تایپ می‌کنه و باید مثل هر اینپوت عددی معمولی رفتار کنه).

## 2. Typography

### 2.1 فونت

- فونت اصلی: **Vazirmatn** (Variable Font) — روی Google Fonts موجوده، ساپورت کامل اعداد لاتین و فارسی داره، مدرن و خوانا، خیلی از محصولات SaaS ایرانی (دیوار، کافه‌بازار) ازش استفاده می‌کنن.
- Fallback stack: `'Vazirmatn', ui-sans-serif, system-ui, Tahoma, sans-serif`
- در Next.js با `next/font/google` لود بشه (نه از CDN خارجی، برای پرفورمنس).

### 2.2 Line-height

- خط فارسی (به‌خاطر دندانه‌ها و شکل حروف) به line-height بیشتری نسبت به لاتین نیاز داره.
- پایه پیشنهادی: بدنه متن `leading-relaxed` (~1.7)، عنوان‌ها `leading-snug` (~1.3) کافیه چون فونت بزرگ‌تره.

### 2.3 Scale (از globals.css)

| Token       | Size | مصرف                           |
| ----------- | ---- | ------------------------------ |
| `text-xs`   | 12px | لیبل کوچک، caption، badge      |
| `text-sm`   | 13px | متن ثانویه، توضیح زیر فیلد     |
| `text-base` | 14px | بدنه اصلی متن، جدول            |
| `text-md`   | 15px | متن دکمه، input                |
| `text-lg`   | 16px | عنوان کارت                     |
| `text-xl`   | 18px | عنوان بخش                      |
| `text-2xl`  | 22px | عدد متریک روی KPI card         |
| `text-3xl`  | 28px | عنوان اصلی صفحه (Page heading) |

- وزن فونت: فقط از ۳ وزن استفاده کن — `regular (400)`, `medium (500)`, `semibold (600)`. از `bold (700)` به بالا فقط برای عدد متریک بزرگ روی KPI card، اونم فقط `semibold` کافیه، بولد خیلی سنگین باعث حس "شلوغ" می‌شه.
- رنگ متن: عنوان‌ها و متن مهم → `text-text-primary`، متن ثانویه/کمکی → `text-text-secondary`، متن غیرفعال/placeholder → `text-text-muted`.

## 3. Color System

منبع واحد: `globals.css`. اینجا فقط **قانون مصرف** رو می‌نویسم، نه مقدار hex (که ممکنه بعداً کمی تغییر کنه).

| متغیر                        | مصرف                                                                                  |
| ---------------------------- | ------------------------------------------------------------------------------------- |
| `background`                 | پس‌زمینه کلی صفحه (`<body>`)                                                          |
| `surface`                    | پس‌زمینه سایدبار و هدر                                                                |
| `card`                       | پس‌زمینه کارت‌ها، پنل‌ها، مودال‌ها                                                    |
| `elevated-surface`           | input، dropdown، popover، هرچی که "روی" یه کارت دیگه شناور باشه                       |
| `border`                     | تمام بردرها — نازک (1px)، کم‌کنتراست                                                  |
| `brand`                      | دکمه اصلی، active nav item، لینک مهم، خط اصلی چارت                                    |
| `brand-soft`                 | پس‌زمینه ملایم پشت آیتم active (نه رنگ solid)                                         |
| `success/warning/error/info` | فقط برای badge وضعیت، آیکون کوچک، متن وضعیت — **هرگز به‌عنوان پس‌زمینه یک کارت بزرگ** |

### قانون طلایی رنگ

۸۰-۹۰٪ صفحه باید خاکستری/مشکی باشه. اگه یک صفحه رو اسکرین‌شات بگیری و بیشتر از ۱۰٪ سطحش سبز بود، یعنی زیاده‌روی شده — یه چیزی رو باید ساده‌تر کرد (احتمالاً یه badge یا border که نباید سبز می‌بود).

### نگاشت وضعیت سفارش (Order Status)

| Status       | رنگ                    | توضیح فارسی روی UI |
| ------------ | ---------------------- | ------------------ |
| `pending`    | `warning`              | در انتظار          |
| `processing` | `info`                 | در حال پردازش      |
| `shipped`    | `brand` (نسخه lighter) | ارسال شده          |
| `delivered`  | `success`              | تحویل شده          |

Badge وضعیت: پس‌زمینه `*-soft`، متن و بردر `*-main` یا `*-darker` — هیچ‌وقت پس‌زمینه solid پررنگ.

## 4. Spacing & Radius

- واحد پایه spacing: مضرب ۴px (استاندارد Tailwind: `p-1`=4px تا `p-8`=32px).
- بین بخش‌های اصلی صفحه (بین KPI cards و جدول مثلاً): `gap-6` یا `gap-8` — فضای باز و آرام، نه فشرده.
- داخل کارت: padding `p-5` یا `p-6`.

Radius (بعد از رفع باگ):

| Token         | مقدار  | مصرف                    |
| ------------- | ------ | ----------------------- |
| `radius-xs`   | 4px    | badge، chip کوچک        |
| `radius-sm`   | 6px    | input، دکمه کوچک        |
| `radius-md`   | 8px    | دکمه معمولی، card کوچک  |
| `radius-lg`   | 12px   | کارت‌های اصلی dashboard |
| `radius-xl`   | 16px   | مودال، پنل بزرگ         |
| `radius-full` | 9999px | آواتار، دات وضعیت       |

هیچ کجا radius بزرگ‌تر از `xl` استفاده نشه — طبق بریف، UI نباید حالت "bubble/playful" بگیره.

---

## 5. Layout & Grid

- **Sidebar**: سمت راست صفحه (طبق تصمیم RTL)، عرض ثابت `240px` (expanded) — قابل collapse به `72px` (فقط آیکون).
- **Header**: ارتفاع ثابت `64px`، شامل: search (سمت... در RTL یعنی نزدیک شروع محتوا)، آیکون نوتیفیکیشن، آواتار/نام ادمین.
- **Content area**: padding بیرونی `px-8 py-6`، پس‌زمینه `background`.
- **Grid کارت‌های KPI**: روی دسکتاپ ۴ ستونه (`grid-cols-4 gap-6`)، روی تبلت ۲ ستونه، موبایل ۱ ستونه (این پروژه اولویتش دسکتاپه چون ادمین پنله، ولی نباید کامل بشکنه روی تبلت).
- Breakpoints: از پیش‌فرض Tailwind استفاده کن (`sm/md/lg/xl`)، نیازی به breakpoint سفارشی نیست.

---

## 6. Cards & Elevation

- بدون shadow سنگین. اگه لازم شد سایه، فقط یه `shadow-sm` خیلی ملایم و مشکی (نه رنگی).
- تمایز سطوح فقط با تفاوت رنگ پس‌زمینه (`background` → `surface` → `card` → `elevated-surface`) + یک بردر ۱px از `border`.
- کارت‌ها هیچ‌وقت بردر ضخیم یا رنگی ندارن، مگر برای state خطا/هشدار (اونم فقط بردر نازک semantic، نه پس‌زمینه).

## 7. Buttons

| Variant     | پس‌زمینه                    | متن                 | بردر          | مصرف                                 |
| ----------- | --------------------------- | ------------------- | ------------- | ------------------------------------ |
| Primary     | `brand`                     | مشکی/تیره (نه سفید) | ندارد         | اکشن اصلی صفحه (ذخیره، ایجاد محصول)  |
| Secondary   | `elevated-surface`          | `text-primary`      | `border` نازک | اکشن ثانویه (انصراف، فیلتر)          |
| Ghost       | transparent                 | `text-secondary`    | ندارد         | اکشن کم‌اهمیت (مثلاً آیکون توی جدول) |
| Destructive | transparent یا `error-soft` | `error`             | `error` نازک  | حذف محصول/سفارش                      |

- بدون گرادیانت روی دکمه‌ها.
- کلاس‌های آماده از `globals.css`: `button--sm`, `button--md` — همینا رو استفاده کن، دوباره از صفر نساز.
- Hover state: فقط کمی روشن‌تر/تیره‌تر شدن پس‌زمینه (`brightness` یا رنگ `-darker`/`-lighter` که در tokens موجوده)، بدون افکت اضافه (بدون scale، بدون glow).

## 8. Components (مشخصات هرکدوم)

### 8.1 Sidebar

- لوگو/نام «Haj PC» بالای سایدبار.
- آیتم‌های نویگیشن: آیکون + متن، پدینگ عمودی راحت (`py-2.5`).
- Active item: پس‌زمینه `brand-soft`، متن و آیکون `brand`، بدون بردر اضافه.
- Hover (غیرفعال): پس‌زمینه `elevated-surface` خیلی ملایم.
- Collapse toggle پایین سایدبار.

### 8.2 KPI Card

- ساختار: لیبل کوچک بالا (`text-secondary`, `text-sm`) → عدد بزرگ (`text-2xl`, `semibold`, `dir=ltr tabular-nums`) → یک خط تغییر نسبت به دوره قبل (٪ با رنگ success/error بسته به مثبت/منفی بودن) + آیکون کوچک trend.
- بدون آیکون بزرگ رنگی تزئینی وسط کارت — این باعث حس "template رایگان" می‌شه، نه premium.

### 8.3 Recent Orders Table

- ستون‌ها: شماره سفارش، نام مشتری، تاریخ (شمسی)، مبلغ، وضعیت (badge)، اکشن.
- ردیف‌ها با `border-b` نازک از هم جدا می‌شن، بدون zebra striping رنگی — یا اگه لازم شد، فقط با یه تغییر خیلی جزئی بین `background` و `surface`.
- Hover روی ردیف: پس‌زمینه `elevated-surface` ملایم.

### 8.4 Sales Chart (Line)

- خط اصلی: `chart-primary` (سبز)، ضخامت متوسط، بدون fill/gradient پرزرق‌وبرق زیرش (حداکثر یه گرادیانت شفاف خیلی ظریف سبز به transparent، اختیاری).
- Grid lines: `chart-grid`، خیلی کم‌رنگ، فقط افقی (خطوط عمودی معمولاً حذف می‌شن برای تمیزی بیشتر).
- Tooltip: پس‌زمینه `elevated-surface`، بردر `border`، بدون shadow سنگین.

### 8.5 Category Breakdown Chart (Bar/Pie)

- طبق بریف: از رنگین‌کمانی پرهیز کن. سبز برای دسته اصلی/برتر، خاکستری‌های مختلف (`chart-secondary`, `chart-tertiary`) برای بقیه دسته‌ها.

### 8.6 Status Badge

- شکل: پیل کوچک (`radius-full` یا `radius-xs`)، پس‌زمینه `*-soft`, متن `*-main` یا `*-darker`, فونت `text-xs medium`.

### 8.7 Modal / Dialog

- پس‌زمینه `card`، بردر `border`، `radius-xl`.
- Overlay پشت مودال: مشکی نیمه‌شفاف ساده (`bg-black/60`) — بدون blur شیشه‌ای اغراق‌شده.

### 8.8 Form Inputs (فرم محصول/سفارش)

- پس‌زمینه `elevated-surface`، بردر `border`، `radius-sm`.
- Focus state: بردر `brand`، یک `ring` خیلی نازک سبز کم‌رنگ (`brand-soft`) دورش — نه glow پررنگ.
- Select دسته‌بندی محصول: از همون ۸ دسته ثابت پروژه (کیس، پاور، رم، مادربورد، SSD، HDD، کارت گرافیک، پردازنده).

## 9. Motion

- Transition پیش‌فرض: `150–200ms`, easing `ease-out`.
- بدون bounce، بدون spring اغراق‌شده، بدون انیمیشن ورود صفحه‌ای شلوغ.
- فقط جاهایی که واقعاً کمک می‌کنه: باز/بسته شدن مودال (fade + کمی scale از 0.98 به 1)، hover رنگ، expand/collapse سایدبار.

---

## 10. Accessibility

- کنتراست متن روی پس‌زمینه (WCAG AA حداقل: نسبت ۴.۵:۱ برای متن معمولی) — چون پالت خیلی تیره‌ست، `text-muted` رو فقط برای متن غیرحیاتی (نه لیبل مهم) استفاده کن.
- Focus ring همیشه قابل مشاهده باشه (رنگ `brand`) — هیچ‌وقت `outline-none` بدون جایگزین نذار.

## 11. Quick Do / Don't Recap

**بکن:**

- خاکستری/مشکی خنثی (نه آبی‌متمایل)
- سبز فقط جای مهم و محدود
- عدد لاتین + `dir=ltr` برای دیتا
- تاریخ شمسی
- سایدبار راست، لاجیکال کلاس‌های تیلویند به‌جای left/right

**نکن:**

- گرادیانت بنفش/آبی، گلو نئونی، افکت RGB
- کارت رنگی بزرگ solid برای وضعیت
- radius بزرگ (بیشتر از 16px)
- بولد بیش‌ازحد یا وزن فونت زیاد
- شلوغی، آیکون‌های تزئینی اضافه
- استفاده مستقیم از `pl-/pr-/left-/right-` به‌جای کلاس‌های logical

## 12. Token Source of Truth

هر رنگ/سایز/radius که در بالا اسم برده شده، مقدار دقیقش در `globals.css` (بلاک `@theme inline`) و `design-tokens.tokens.json` تعریف شده. اگه این سند و اون فایل‌ها باهم اختلاف داشتن، **globals.css برنده است** (چون همونیه که واقعاً build می‌شه).
